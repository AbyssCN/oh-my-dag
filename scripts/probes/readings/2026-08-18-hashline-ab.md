# hashlineEdit 开 vs 关 —— 加难度版 A/B

**问题**(owner 2026-08-18):hashline 行锚定编辑感觉没带来提升,反而伴随不少 bug,该不该关?

**动手前先把账算清楚**(证据在 `docs/silent-failures.md` 与 git log):
- 真跟它有关的两件:`221e2e4`(路径嵌在 patch 正文 → `filesTouched` 与写沙箱各要解析一次,
  漏一处就把成功节点判成 `empty-done failed`)· `b87196e`(弱模型撞 stale 标签后继续叠行号编辑
  → 复合腐烂,得加 fail-closed 闸)。
- 算错在它头上的一件:`impl` 508s `spin-fused` 卡在 `hashline_edit` —— 根因是 `computeSig`
  路径签名取头 60 字符而 jail 根 73 字符,任意两文件签名相同(`1c07703` 已修)。
- 今天新查出的洞:hashline **一行碰撞台账都不写**(`src/harness/hashline.ts` 零个 `touch` 引用)。
- 提升那一侧:**本仓零读数**。唯一相关数字是外部的(编辑格式换动,Grok Code Fast 6.7%→68.3%),
  而本仓当时的裁决就是「等 EDIT-Bench 型对照进 gauntlet 再动」。这一轮就是那个对照。

## 四要素(点火前写死,事后不改)

| 要素 | 内容 |
|---|---|
| 单一变量 | 只动 `createAgentLeafRunner({ hashlineEdit })`。座位、题面、超时、隔离世界构造、`--no-hint` 全部两臂相同 |
| 成败信号 | **可以关** = 关闭臂通过题数 ≥ 开启臂 −1 **且** `tokensIn` 中位 ≤ 开启臂 ×1.10;**该留着** = 关闭臂通过题数少 ≥2 **或** `tokensIn` 中位 ≥ 开启臂 ×1.25;两者都不满足 = **未判定**,读数两侧都记,默认值不动 |
| 对照基线 | 同一天、同一批 4 题、座位钉死 `minimax-cn:MiniMax-M3`(生产 leaf 座),开启臂现跑,不拿昨天的数当基线 |
| 收哪些数 | 每题每臂:`verdict` · `tokensIn`/`tokensOut` · `toolCalls` · `wallMs` · 判分命令 exit · 是否碰受保护路径 |

**难度按 hashline 该显效的维度抬**(owner:提高难度):
1. **大文件优先** —— 行锚定编辑治的是行号错位,小文件天然显不出差别。选中的四题里两题的实现文件是
   `src/harness/dag/engine.ts`(**3,915 / 3,943 行**),另两题 723 行 / 448 行。
2. **去掉位置提示** —— 两臂同开 `--no-hint`,题面不再给「相关实现文件」。被测方要自己定位,
   读改轮次变多,正是行锚定该显效的场景。

题库为此从 4 题扩到 7 题(`omd-bench extract --limit 400`,扫 400 个 commit,49 个形状干净的候选,
绝大多数被合约第 4 条拒掉 —— RED 必须是断言失败而不是加载失败)。

⚠ **碰撞台账那一列这轮收不到**:`omd-bench` 的 leaf 不传 `touch` 会话,隔离世界里根本没有台账。
记 NULL 不记 0。hashline 不写台账这件事是**读代码得出的**,不靠这轮读数。

### 判词(按点火前写死的判据)

**"可以关"成立**:通过题数 4 = 4(≥ 开启臂 −1),`tokensIn` 中位 404,930 ≤ 675,683 × 1.10。

**但读数比判词弱,三条都要连着读**:
1. 逐题配对 **2:2** —— off 在两题上便宜、on 在另两题上便宜。中位数占优是分布效应
   (被 `dc46c885` 那一格拉出来的),不是一致方向。
2. 每格 **n=1**,而同臂方差昨天实测 1.4–1.8×(`2026-08-18-leaf-toolface-ab.md`),与效应同量级。
3. **它该显效的地方没显效**:两道题的实现文件是 3.9k 行的 `engine.ts` 且去掉了位置提示,
   行锚定编辑治的行号错位就该在这里显出来 —— 结果 off 赢一题输一题。

所以这一轮的**正确读法是「没有证据支持开着」,不是「证明了它有害」**。

机制上 on 更贵说得通:hashline 要求"先 read 拿标签再 edit",标签每次 apply 后失效强制重读,
于是工具调用中位 26 vs 21.5,每多一轮就多重发一次上下文。

### owner 裁决(2026-08-18)

**先关掉**(`src/mcp/assemble.ts` 两个装配点 `hashlineEdit: false`),开关与实装都留着,
优化 + 补测之后再考虑上线。跟踪见 GitHub issue。

关掉的连带收益:碰撞台账回到 strict 档(hashline 一行不写,`edit`/`write` 写),
`hashlinePatchPaths` 那两处解析(filesTouched / 写沙箱)在默认路径上不再被走到。
