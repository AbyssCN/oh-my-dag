# 为什么有 omd

[← README](../README.zh-CN.md) · [English](why-omd.md) · [上手](guide/getting-started.md) ·
[架构](architecture/overview.md)

这是首页那句话的长版本。它只讲两件事:**omd 占哪一层**,以及**谁有资格说这活干对了**。
不用装就能读。

---

## 一 · 七个 harness,一个共同前提

把 2026 年的开源编码 agent 拆开看,架构分成四派。

**原生内核派** —— codex 和 oh-my-pi,把热路径沉到 Rust,换来沙箱纵深和一个真的 tokenizer。
**事件溯源派** —— deepseek-harness、opencode、kimi-code v2,会话日志是唯一真相源,界面、恢复、
遥测全是它的投影。**产品生态派** —— qwen-code 和 kimi-code,围着自家模型铺全端。
**标准工程派** —— gemini-cli,策略引擎、OTel、evals、性能基线,一样不缺。

它们差别巨大。有一件事上完全相同。

**每一个都是会话层工具。** 工作单位是一个回合。主循环都是 ReAct:采样模型、跑它要的工具、
把结果回灌、再来一轮。让它们变好的所有东西 —— 上下文压缩策略、审批姿态、沙箱嵌套、事件重放 ——
都在服务于同一件事:让那个循环活得更久、表现更好。

而循环在模型说自己干完了的时候结束。

这就是那个前提。**做没做对,是由模型报告的。** 不是量出来的,不是查出来的 —— 是报告的。
「做完了」是模型吐出的一句话。

这不是在批评谁。会话层工具在结构上做不到别的:**产出这件活的那一次前向传播,和评判这件活的
那一次,是同一次** —— 同一个上下文,同一套信念。不跨出会话,判词就没有别的地方可来。

## 二 · 当「做完了」只是一句话,代价是什么

这些失败一点都不稀奇。它们是你已经遇到过的那些。

**它说干完了,而它没有。** 摘要说文件改好了,`git diff` 说没有。没有任何东西报错,
所以没有任何东西变红。

**上下文用完了,一切从头再来。** 四十分钟的活,大部分是对的,而恢复路径是重新提问、
重新付一遍钱 —— 因为单位是会话,而会话没了。

**你分不出真通过和空通过。** 模型提了一条验收测试,测试过了。它过是因为活干对了,
还是因为这条测试对着任何东西都会过?没人查过。**也没法查** —— 判据和活出自同一个地方。

**方法只活在某一个人的 prompt 里。** 你审 diff 的路数、你追根因的路数、锁方案前的纪律,
它们住在一个文本文件里,好模型大部分时候会照做,上下文一长就悄悄跳过。

每一条都是**静默**失效。不是崩溃,不是报错。系统报告成功,而成功是假的。
你是后来从别处才知道的。

## 三 · 换一个工作单位

omd 不在会话层。它是底下那一层,而让其余一切成为可能的那个改动,一句话就能说清:

**工作单位是一个节点,不是一个回合。**

回合是不透明的。它没有声明过的输入、没有声明过的输出、没有依赖、没有能活过这次对话的身份。
你没法续跑它的一半,没法并行跑两个还确信它们不撞车,没法给这个派便宜模型、给那个派贵的,
也没法把其中一个交给另一个模型家族要第二意见。这些性质,回合在结构上就没有。

节点全都有,因为接口是一张**类型化 plan** —— 一份 zod 校验过的 JSON 图 `{ nodes[], outputs[] }`。
这张 plan 是一道**接缝**:它下游的机器根本不关心它从哪来。conductor 模型可以画它;
编译器可以从一张决策地图零 LLM 地生成它;你可以手写它。三条路产出的是同一个对象,
并且在执行之前都要过同样四道纯函数 —— 剪掉死节点、按语义指纹去重、过证据闸、给每个节点钉一个模型。
零 IO,零随机,同输入同输出。

这一个改动之后,其余的都跟着来:

- **依赖是声明出来的,所以并发是安全的。** 引擎按就绪集调度:输入齐了的全部一起跑。
- **每个节点原子存档。** 续跑复核输入哈希,输入没变的节点保持绿、**不重复计费**,只重跑剩下的。
- **每个节点可以带自己的模型。** 这就引出座位 —— 18 个,而座位是**模型选择轴,不是角色轴**。
  判错代价高又稀少的地方上强的;量大且有确定性检查兜底的地方上便宜的。
- **每个节点可以被单独判。** 这才是全部的重点。

## 四 · 判词来自模型之外

一道阶梯,按顺序,不许跳级。

### 第一级 —— 机械 oracle,零 LLM

一个 `command` 节点跑 `tsc`、跑测试、跑扫描器、或者跑你自己的脚本,退出码必须等于 `expect_exit`。
环里没有模型,所以没有任何东西可以被说服。旁边并排两件:**写集对账** —— 这个节点是不是真写了
它声称写的那些文件?**产物闸** —— 它点名的文件在盘上到底有没有?一个报告了自己从未创建过的文件的
节点,判败。一张不存在的「已审阅」截图,判败。

**而判据自己,在被信任之前要先过一场考试。** 这一段值得读两遍,因为它堵的是别的验收方案都留着的
那个洞:**一条永远会过的判据,和一条因为对的理由才过的判据,从外面看长得一模一样。**

所以引擎把这条验收命令放进一个临时世界**跑两遍**:

- 一遍在**什么活都还没干的时候**。还绿 —— 说明它跟这个任务毫无关系。
- 一遍打在一个**故意做错的产物**上 —— 分类器必须连命令一起把这个错样本交出来,正是为了让这一探
  成立。还绿 —— 说明它分不出对的答案和错的答案。

两种结果都让目标降级成 exploratory,而不是收下一个假的通过。两条探针都刻意是 **fail-open** 的:
探针本身跑不起来时,判据照收,但被**标成未经证明**,而不是把整趟跑挡下来 —— 这样「这个目标到底
有没有被什么真东西判过」才是一个能读的数,而不是一种信念。真源:`src/harness/goal/acceptance-gate.ts`。

**下面这一段,比任何功能清单都更能说明这套做法为什么值得。**

有很长一段时间,判别力探针红过的次数是**零**。账本里 348 次跑,69 次真跑过它;那个窗口里的三次降级,
**全部来自另一条探针**。66 比 66,零方差。

一道从不触发的闸,要么什么都没守,要么坏了。而这个仓自己的规矩是:**一个在任何干预下都不动的数,
通常量的是尺子,不是被测物。** 它量的就是尺子。那个「故意做错的世界」当时是一个**空的临时目录**,
里面只放了那份错样本 —— 而在空目录里,`bun test`、`tsc`、任何相对路径检查,不管你放什么进去都会失败。
探针问的根本不是「这条判据分不分得出对错」,它问的是「这条命令拿到仓外会不会挂」,而答案恒为「会」。

现在那个反面世界是真仓的一份副本(`git archive`,外加一条 `node_modules` 软链,好让副本真的跑得起来)。

重点不是这个 bug 存在过。**重点是它被找得出来** —— 因为那个判词是一个五值词表、逐跑记进账本,
所以某一列上一个平坦的零才是看得见的。假如这道闸报的是一个布尔值,它今天还是绿的,而且还是没用的。

### 第二级 —— 来自另一个模型家族的 verifier

有些事没有退出码能定。这份摘要忠不忠于原文?这个设计到底满不满足契约?这些交给一个 verifier:
它对着原始要求读结果,产出 pass 或 fail。

**它必须来自与作者不同的模型家族。** 同家族自审会复用同一个盲点:它造出来的坏计划,
它自己看不出坏。而且它的职责被写成**攻击结果**,不是盖章 —— 一个被要求确认的审查者,就会去确认。

判 fail 就升级 —— 换更强的 conductor、把失败原因注进去、重画。被点名的节点及其下游重跑,
其余原样复用。真源:`src/harness/verifier.ts`。

### 第三级 —— 人

前两级都定不了的,升给人。不是拖延,也不是替人拍板。

### 必须一直记着的那个推论

**oracle 绿 ≠ 语义对。** 这台引擎真的发过这样一次改动:`tsc` 干净、整套测试全绿,
而一处状态映射的标签是**反的**,配套测试还把这个错固定了下来 —— 注释写对了,断言写反了。
**测试和实装由同一次改动一起产出时,它们会一起错,并且互相背书。**

这正是第一级抓不到的东西。也是第二级不可省的原因,以及这道阶梯为什么是阶梯而不是菜单。

## 五 · 可靠性在外,创造力在内

只说前一半,会得到一个可预料的失败:把模型机械化掉,用规则替掉判断,直到整个系统只剩下
它那些规则的聪明程度。所以两半要一起说:

> **可靠性来自模型之外。创造力来自模型之内。**
>
> **闸负责判** —— 确定性、零模型、fail-closed。模型「看一眼」不算闸,因为它静默地没跑时,
> 没有任何东西会红。
>
> **模型负责生成** —— 做什么、怎么做、还缺什么。**闸之内,别把这件事换成规则。**
> 用一条机械规则替掉生成,等于把模型的智力压到那条规则的表达力。

三条推论,能裁掉真实的设计争论:

1. **确定性检出器是地板,不是天花板。** 对抓过的 URL 做一次集合差,是「我们漏读了什么」的
   极好地板。但它是「接下来该看什么」的极差替代品。
2. **终止归引擎,内容归模型。** 轮数上限、连续 K 轮无进展就停、法定人数 —— 引擎来数。
   问模型「我们干完了吗」,等于把闸存在的理由那个静默失效原样请回来。
3. **闸设在接缝上,不设在每一步上。** 把一个能干的模型当一个能干的人对待:
   你在判错代价高的地方查工作,而不在他思考的时候扒着肩膀看。

同一条分野也出现在控制流上。omd 出厂 13 个原语 —— `parallel`、`pipeline`、`loop-until`、
`verify`、`judge`、`discovery`、`iterate`、`tournament`、`router`、`race`、`escalation`、`saga`,
以及默认关闭的 `escape-hatch`(要设 `OMD_ESCAPE_HATCH=1`)。**模型挑形状和参数。
循环、分支、终止条件、打分,留在代码里。** 住在 prompt 里的控制流,是模型跑到一半会忘掉的控制流。

## 六 · 重叠到底在哪

诚实的邻居,诚实地写。

|  | 会话层 harness | workflow 引擎<br>(LangGraph, Temporal, Restate) | eval / 闸框架<br>(Inspect, promptfoo, Braintrust) | **omd** |
|---|---|---|---|---|
| **工作单位** | 一个回合 | 你手写的一步 | 一次打分 | **类型化图里的一个节点** |
| **图从哪来** | 没有图 | 你写 | 没有图 | **模型画、编译器出、或你手写 —— 引擎只校验它合不合法** |
| **谁判对错** | 模型说了算 | 你写的断言 | 你写的评分表 | **oracle → 跨家族 verifier → 人,按这个顺序** |
| **跑一半断了** | 会话结束 | 按你的策略重试或补偿 | 打完分就结束 | **每节点 checkpoint;续跑保持绿节点绿,且不重复计费** |
| **闸什么时候跑** | — | 你把它放哪就哪 | 事后,在存档的 trace 上 | **在产出这件产物的同一趟跑里** |
| **怎么调它** | 你跟它聊天 | 你嵌进应用代码 | 你从 CI 调 | **经 MCP,从你手上那个 agent** |

图不是新东西 —— LangGraph 和 Temporal 都跑图,而且持久化做得比大多数人好。闸也不是新东西 ——
`tsc` 和一套测试比这些都早。**在这一台引擎里合到一起、并且是被一个编码 agent 调用而不是嵌进
某个应用的,是这几件:** 类型化 plan 当交换格式、闸跑在产出这件产物的那一趟里而不是事后在 trace 上、
跨家族核验、每节点原子续跑,以及一层 MCP 接口 —— 让你已经在用的那个会话层驱动上面全部,
而不用改用什么新东西。

**你要写应用代码、要持久工作流,用 workflow 引擎。你要离线给模型输出打分,用 eval 框架。
你的活一次对话装得下,用你手上的编码 agent,别往下读了。** omd 管的是夹在中间那种:
活大过一次对话,而且必须真的编译得过、真的引得出、真的跑得完 —— 并且你不愿意就「它到底做没做到」
这件事听模型自己说。

### 这份版图是 omd 自己跑出来的,你也可以重跑

「别人都没凑齐这几件」这类话通常是装饰,所以我们把它做成可核查的。那七条性质是:
类型化 DAG plan 当**接口**;确定性的事前闸;退出码 oracle;写集对账;跨模型家族的 verifier;
每节点 checkpoint 与续跑;以及经 MCP 暴露,让任何会话层 harness 都能调。

跨三层(会话层 harness / workflow 引擎 / eval 与闸框架)的调查回来的结果是:
**没有任何一个系统拿到超过部分的牌**,而且缺口是结构性的,不是偶然没人做:

- **写集对账在 coding-agent 域里一个产品都没有。** 它必须在一次工具调用返回的那一刻读真实副作用,
  而编排引擎只提供「你自己在节点里写对账代码」—— 没有可接的文件系统观测接缝。
- **跨家族核验作为模式存在、作为论文存在,但不作为 schema 约束存在。** 各家验证层把 verifier
  实现成**再调一次 LLM**,模型的家族身份从不进入 schema、不进入判词、不进入 checkpoint。
  **没被记下来的东西,强制不了。**
- **现有的 MCP 接口都是工作流级的运维面** —— 启动、取消、监控、部署、查历史。
  没有一个暴露「可提交的 plan」或「可查询的逐节点证据面」。

两条诚实的附注。这份调查是机器管线在抓到的信源上产出的,所以里面的单条引用当线索看,别当定论。
另外,「没人凑齐」不等于「这个组合显然是对的」—— 它是一个该去看看的理由,不是一个证明。

两条附注之后还站得住的那一点是:**这个问题一条命令就答得出来,而报告带着信源在盘上,
不在一张 PPT 里。**

```bash
bun run scripts/dag-research.ts "<换成你自己的问题>" --deep
```

## 七 · omd 刻意不做什么

- **不是编码 CLI。** 没有让你常驻的 TUI。(`omd tui` 存在,还在开发中,而且不是这个项目的重点。)
- **不是聊天 agent。** `conductor_chat` 是引擎上的一个座位,不是一个产品。
- **不是 eval 框架。** 你不用给它送 trace;闸跑在那一趟跑里面。
- **它不自己交付。** `map_deliver` 是 **owner** 亲手拉的那道闸。自动化可以自己调研、抓取、
  规划、争论。**改文件永远是人的决定,每一次都是。**
- **不锁厂商。** MIT、Bun 上的 TypeScript,而且每个座位都是一个 `provider:model` 坐标 ——
  任何 OpenAI 兼容的都行。
